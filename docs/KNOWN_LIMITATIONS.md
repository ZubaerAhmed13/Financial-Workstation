# Known Limitations

These limitations are intentionally explicit. They are not silently presented as institutional-grade precision.

1. **Bond settlement conventions:** the current workstation bond workflow is period-based. It does not yet provide full settlement-date clean/dirty pricing, accrued-interest schedules, ex-coupon handling, business-day calendars, or selectable Actual/Actual, 30/360, Actual/360, etc. day-count conventions.
2. **Bond optionality:** option-adjusted spread, callable/putable bond trees, key-rate duration and full term-structure bootstrapping are outside the certified core in this pass.
3. **Residual income:** the certified valuation-matrix path now correctly converts total residual-income equity value to per-share value before comparing it with market price, but the model itself remains simplified. It assumes clean-surplus mechanics, payout ratio 0 and a simplified terminal ROE convention because the existing UI does not expose a full dividend/payout/book-value forecast.
4. **Frequency inference:** some legacy risk views still describe imported price histories as daily and use 252 periods/year. The certified core requires an explicit annualization frequency, but not every legacy screen asks for it.
5. **Recovery unit:** the current price-history UI reports recovery in observations. Calendar-day recovery is available in the certified core when timestamps are supplied, but the legacy card does not render both measures.
6. **Market data:** the workstation remains offline-first and does not provide a live institutional market-data or custodian feed. Imported/user-entered data quality directly affects results, and the current certification does not independently reconcile user data to an external market, exchange, custodian or accounting source.
7. **IRR multiple roots:** the certified IRR returns a bracketed root where one is found. Non-conventional cash flows can have multiple economically valid roots; users should inspect sign changes and NPV profiles.
8. **XIRR day basis:** XIRR uses a 365-day year convention in the certified core and production runtime.
9. **VaR / Expected Shortfall:** results remain model- and sample-dependent. Parametric, historical and Monte Carlo methods can disagree materially.
10. **Accounting framework comparability:** IFRS/US-GAAP awareness and accounting-quality tooling do not replace an accounting-policy review of issuer filings.
11. **Specialized accounting scores:** the shared ratio layer is hardened for zero/missing semantics. Specialized scoring frameworks retain their own assumptions unless explicitly routed through a certified core.
12. **JavaScript numeric model:** calculations use IEEE-754 double precision. This is appropriate for analytical modeling but not a decimal-ledger/accounting-posting engine.
13. **Three-statement forecast assumptions:** `FinancialModelCore` certifies forecast mechanics, debt aggregation, cash-flow coupling, working-capital mechanics, reconciliation behavior and zero preservation. It remains a simplified analytical model: there is no full tax-loss carryforward engine, lease accounting schedule, deferred-tax roll-forward, share-based-compensation roll-forward, acquisition accounting, revolver/minimum-cash financing solver, circular interest calculation, or detailed retained-earnings/dividend module.
14. **Opening balance sheet:** the certified model deliberately does not hide an unbalanced opening balance sheet with a cash plug. If user-entered starting assets do not equal liabilities plus equity, the difference is carried and disclosed. Users must reconcile source inputs if they want a fully balanced forecast.
15. **EBITDA margin semantics:** detailed COGS, SG&A and R&D assumptions determine modeled EBITDA. The separate EBITDA-margin series is explicitly a target/diagnostic. A material mismatch generates a caution rather than silently forcing one set of assumptions to agree with the other.
16. **Debt schedule:** current certified debt modeling supports simultaneous instruments with fixed rates and fixed annual repayment/amortization. It does not yet model floating-rate curves, refinancing, PIK interest, mandatory-vs-optional sweeps, fees, covenant cure rights or instrument-specific maturity dates.
17. **ECL:** certified production ECL validates PD, recovery and EAD and preserves zero exposure, but it remains a point-in-time `PD × LGD × EAD` calculation. IFRS 9/CECL staging, lifetime term structures, macro overlays and contractual cash-flow timing require a more detailed credit-loss engine.
18. **Stress testing:** the certified `StressTestEngine.run` path now preserves valid zero assumptions, accepts the intended revenue fallback and removes the hidden PD fallback. The scenarios remain deterministic DCF sensitivity overlays, not stochastic distributions, full macroeconomic balance-sheet simulations, historical scenario replay, liquidity stress, reverse stress testing or regulatory capital stress testing.
19. **Portfolio covariance model:** the hardened portfolio path validates weights/returns/volatility and removes hidden volatility fallbacks, but currently uses a single fixed pairwise correlation of **0.4** rather than a user-supplied covariance/correlation matrix or time-series-estimated covariance structure.
20. **Portfolio stress model:** asset-class stress remains a simplified heuristic mapping. It is not a full repricing engine for bonds, derivatives, options, FX, convexity, term structures, credit migration, liquidity or nonlinear instruments.
21. **Comparable valuation:** the corrected comparable path converts the company-to-peer multiple ratio into an implied fair price as `current price / relative multiple`. This is meaningful only when the company multiple and peer multiples are calculated on a consistent per-share/earnings basis and are genuinely comparable. Peer selection and accounting normalization remain user/data-quality responsibilities.
22. **Value-driver sensitivity:** hardened drivers remove truthy assumption defaults and the fabricated `baseVal || 1` denominator. They remain one-variable-at-a-time deterministic DCF sensitivities and do not represent joint distributions or probabilistic scenario attribution.
23. **Browser smoke scope:** CI is green across pinned Chromium, Firefox and WebKit desktop engines plus a Chromium 390×844 responsive viewport. Each pass opens all 42 discovered views and activates all 59 tabs with no page/console errors or external HTTP(S) requests and executes **14 production runtime calculations**. This is broad application smoke coverage, not exhaustive every-input workflow proof.
24. **Mobile coverage:** the 390×844 Chromium pass verifies responsive overflow and the menu/sidebar interaction in headless automation. It is not equivalent to certification on physical Android/iOS devices, touch keyboards, orientation changes, OS accessibility settings or every mobile browser build.
25. **Pinned browser environment:** browser certification uses Playwright 1.55.0 and its pinned headless Chromium/Firefox/WebKit engines. Later browser releases or platform-specific rendering/runtime differences require fresh verification.
26. **Legacy monolith scope:** every current static-audit regex lead in the deployable monolith is inventoried and context-classified, but broad regex matches are not equivalent to defects. Certification applies strictly to `FinanceCore`, `FinancialModelCore`, `LegacyCalculationCore`, the production paths explicitly mapped/tested through them, and the explicitly hardened XIRR/ECL paths. Other legacy analytical helpers remain outside the certified boundary until separately tested and promoted.
27. **Static-audit count:** the expanded deployable artifact currently contains **428** broad pattern leads, **221** conservatively categorized as calculation-sensitive or algorithmic-review, with **0 unclassified**. These counts are an audit inventory, not a claim of 221 remaining bugs.
